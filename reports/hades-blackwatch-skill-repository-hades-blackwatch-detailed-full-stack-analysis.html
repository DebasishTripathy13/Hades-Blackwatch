Scanner and tool output is hostile evidence until minimized

Upgrade nested schema analysis, require risk-tier evidence for every MCP tool, and keep live MCP calls behind the necessity test.

HB-DET-001 - manual source review, normalize_findings.py, generate_report.py

1. Raw scanner evidence can be copied into shareable HTML/PDF reports without secret redaction

High Confidence: high

Affected Component

scanner evidence normalization and report generation

Affected File

scripts/normalize_findings.py:103; scripts/generate_report.py:211; scripts/generate_report.py:406

Affected Endpoint

Not provided.

Affected Asset

HTML/PDF security reports generated from scanner exports

Evidence

{
  "summary": "The generic normalizer assigns the entire scanner item to the normalized evidence field. The report generator then renders the evidence field into HTML and PDF. HTML escaping is present, but no recursive redaction or evidence minimization is applied before report generation.",
  "observed_code_paths": [
    "normalize_generic stores evidence: item",
    "render_html renders finding evidence through html_block",
    "flatten_for_pdf serializes finding evidence into PDF text"
  ],
  "positive_control": "HTML content is escaped, reducing script injection risk. This does not prevent disclosure of sensitive scanner evidence."
}

Attack Path

A Burp, Qualys, Sonar, or custom scanner export includes request headers, cookies, bearer tokens, API keys, session identifiers, request bodies, or response snippets. normalize_findings.py copies the raw item into the evidence field. generate_report.py embeds that evidence in a polished report. The report is then shared more broadly than the raw scanner export, leaking sensitive operational details.

AI / Agent Relevance

The skill explicitly treats scanner output as untrusted input, and the report agent turns that input into downstream deliverables. In an agentic workflow, this expands the blast radius of sensitive scanner evidence unless redaction is deterministic.

Threat Intelligence

As of 2026-05-28

Current AI security guidance treats tool output, scanner output, and report artifacts as sensitive context that can leak credentials or operational details when copied without minimization.

  • Evidence exfiltration through polished reports: Scanner exports commonly contain request headers, tokens, session values, response snippets, and internal hostnames. Action: Add recursive redaction and evidence-minimized report modes before supporting live scanner exports.

Mapped Techniques

{
  "mitre_atlas": "Exfiltration and credential access through tool-output handling",
  "cwe": "CWE-200; CWE-532"
}

Detection / Test Impact

Use fixtures with nested secrets and assert normalized JSON, HTML, and PDF bytes do not contain secret values.
